到底谁在谁下面

实测于 2026-09-23 · 墨尔本大学

结论：你说反了。不是 LMS 在 Canvas 下面，是 Canvas 挂在 LMS 下面。
学校先有一个「学习管理系统」的地盘（lms.unimelb.edu.au）， 然后在这个地盘里塞了一个叫 Canvas 的软件（canvas.lms.unimelb.edu.au）。

一、域名要从右往左读

这是最容易搞反的地方。域名不是「从大往小」排的，是左边最具体、右边最大—— 右边的那个拥有左边的那个。

二、LMS 是「类别」，Canvas 是「牌子」

LMS = Learning Management System，学习管理系统。 它不是一个软件的名字，是一类软件的统称——就像「快递柜」不是某个品牌。

说法是什么
LMS类别。泛指所有管课程、管作业、管成绩的系统
Canvas牌子。做出 LMS 这类东西的一个具体产品
Moodle / Blackboard别的牌子，跟 Canvas 是竞品

所以「墨尔本大学用的 LMS」和「墨尔本大学用的 Canvas」说的是同一件事—— 学校选的牌子就是 Canvas。你在网址里看到的 lms.unimelb.edu.au 是学校给这块地盘起的通用名字：万一哪天换成 Moodle，域名不用改， 换个软件塞进去就行。

三、实测：Canvas 真会把你送回 LMS

我实际发请求验证了。用浏览器身份访问 Canvas 的首页，它不自己显示页面， 而是把你交给 lms.unimelb.edu.au/canvas：

顺便解释两个数字

  • 401 不是错误，是正常。它的意思是「我认识这个地址，但你没出示证件」。 Canvas 回的是标准 JSON：{"status":"unauthenticated"} —— 接口活着，就等你的 token。
  • 403 是「不让看」。门户首页挡掉了非浏览器访问（我换成 Chrome 的身份再试， Canvas 那条就变 200 了）。这不影响我们——我们不走网页那条路。

所以 config.json 里写的地址是对的

配置文件里那一行是：

"base_url": "https://canvas.lms.unimelb.edu.au"

程序会自动在后面补 /api/v1/...。也就是说它直接敲 API 那扇门， 不经过 LMS 门户、不经过跳转、不碰网页——上面图里右边那条路。 这也是为什么它不需要登录、不需要模拟浏览器点击。

四、跟你要做的事有什么关系

你要生成 token 的地方，在 Canvas 里面，不在 LMS 门户里。所以：

  • 浏览器打开 Canvas，正常登进去（会先经过 lms.unimelb.edu.au/canvas，这是正常的）
  • 进去之后找 头像 → Account → Settings → Approved Integrations → + New Access Token
  • 生成的那串字符，就是程序敲 API 那扇门要出示的证件

万一看不到 + New Access Token 按钮

那说明墨大可能把学生自助生成 token 的功能关掉了（教职工走审批流程）。 别自己瞎试、别去找别的办法绕过——告诉我，我换备选方案 （用 Canvas 个人日历的订阅链接，代价是看不到「交没交」的状态）。
